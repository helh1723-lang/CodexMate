### 2.2 测试策略说明

适配器测试通过**注入执行器**（`GitHub` 构造函数第二参数）在**进程边界**替换 `gh`，而不是替换被测对象本身。因此退避、条件请求、幂等分支跑的都是真实适配器代码。`Service` 同样可注入 GitHub 工厂，同步对账逻辑用的是真实 `decodeTask` / `validateGraph` / 配置解析。

## 4. 未验证（需要额外条件）

以下结论目前**没有证据**，请勿在文档或汇报中当作已完成：

1. **跨网络双人端到端。** 需要两台处于不同网络的机器、两个不同的 GitHub 账户、两个不同的 Codex 账户、一个共享的真实仓库。
2. **真实 Issue → worktree → Codex → 草稿 PR → 审查 的完整链路。** 需要真实 Codex 额度与真实仓库写权限。
3. **半成品 checkpoint 跨用户接续**（A 做到一半交给 B，B 从精确 SHA 新建自己的线程完成 PR）。
4. **多设备租约的跨机故障注入**（网络分区、旧 Worker 复活、协调器重启）。
5. **跨平台安装与签名自更新的实操**（Windows / macOS / Linux 的实际安装、升级、回滚）。
6. **README 与文档中描述的操作流程，仅在本机演练模式走通，未在真实仓库走通。**

## 7. 结论

**已经可以声称的：**

- 代码完整实现了 PRD 到 v1.1 的能力面，并能在本机构建、运行、通过 44 个自动化用例与 2 个浏览器 E2E。
- 安全相关的核心控制（密钥扫描、路径与范围校验、审批绑定、退避与条件请求、只读沙箱配置、本机 HTTP 防护、幂等写入）都有可复现的测试证据。
- 演练模式零风险可完整走通协作流程。

**不能声称的：**

- 「双人跨网络协作已验证」。
- 「额度不足自动接力已跑通」。
- 「多人调度不双写已证明」。
- 「正式分发已可用」（签名链路已验证，但跨平台安装未验证）。

**建议的下一步**（按价值排序）：

1. 准备一个真实测试仓库 + 第二个 GitHub 账户，跑通 T01 / T03 / T04 / T06 / T09。
2. 为 `coordinator` 补跨设备故障注入测试；在此之前保持客户端自动抢占禁用。
3. 补 MCP 客户端联调与跨平台安装实测。
